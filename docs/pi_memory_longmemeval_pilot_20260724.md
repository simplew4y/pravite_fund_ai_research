> 📝 官方基准：[LongMemEval](https://github.com/xiaowu0162/LongMemEval)

## 📝 1. 为什么选择 LongMemEval-S

- 📝 它直接测量长对话记忆，不把普通知识问答或模型常识误算成记忆能力。
- 📝 六类题型同时覆盖单会话用户事实、助手信息、隐含偏好、多会话聚合、知识更新和时间推理。
- 📝 `LongMemEval-S` 是官方 500 题短版，适合先做可复现的本地分层 pilot；本次不使用规模高得多的 LongMemEval-V2。
- 📝 每道题带官方答案会话 ID，可以把“是否搜到证据”和“最终是否答对”分开分析。

## 📝 2. 测试设计

- 📝 从六类题型各确定性抽取 5 题，共 30 题；随机种子固定为 `20260724`。
- 📝 每题运行两个条件，共 60 次真实 Pi 回答：
  - 📝 `memory`：将官方 haystack 会话保存为隔离 Markdown，使用 `pi-memory@0.4.0` 的原生 `memory_search` 检索。
  - 📝 `baseline`：相同 Pi、相同 reader、相同问题，但记忆目录为空。
- 📝 Reader 使用 `qwen3-max`；裁判使用 `gpt-5.6-sol`，按官方各题型评分规则输出 Yes/No。
- 📝 检索使用 qmd `keyword`，每次最多返回 10 条结果，每题最多搜索 3 次。
- 📝 30 题累计加载 1,451 个历史会话、15,173,018 个字符；平均每题 48.37 个会话、505,767 个字符。
- 📝 检索命中定义为：官方 `answer_session_id` 出现在 Pi 原生 `memory_search` 的工具结果中。
- 📝 本次测的是“已物化历史的检索 + 回答”，不测 Agent 是否会在原始在线对话中自主判断和持续写入哪些记忆。

## 📝 3. 数字结果

| 📝 指标 | Memory | 空记忆 Baseline | 📝 解释 |
| --- | ---: | ---: | --- |
| 📝 准确率 | 36.7%（11/30） | 10.0%（3/30） | 记忆带来 `+26.7` 个百分点 |
| 📝 可回答题准确率 | 33.3%（9/27） | 0.0%（0/27） | 基线的 3 个正确答案全部来自正确拒答 |
| 📝 正确拒答率 | 66.7%（2/3） | 100.0%（3/3） | 记忆会增加被旧信息误导的风险 |
| 📝 P50 时延 | 16.27 秒 | 11.40 秒 | 记忆中位请求多 4.87 秒 |
| 📝 P95 时延 | 24.12 秒 | 18.54 秒 | 两组都没有超时 |
| 📝 平均 token | 2,635 | 1,643 | 每题多 993 token，即 `+60.4%` |
| 📝 总 token | 79,055 | 49,277 | 30 题多消耗 29,778 token |
| 📝 成功率 | 100%（30/30） | 100%（30/30） | 60 次 Pi 调用均正常结束 |

- 📝 整轮墙钟耗时 16.20 分钟；串行执行，不是并发吞吐测试。
- 📝 Memory 平均时延 16.99 秒，较 baseline 多 6.66 秒，即 `+64.4%`。
- 📝 `memory_search` 调用遵循率 100%，平均每题调用 2.50 次；20/30 题用满 3 次搜索。
- 📝 官方答案会话命中 22/30，命中率 73.3%；命中后答对 10/22，即 45.5%，未命中时答对 1/8，即 12.5%。
- 📝 30 个隔离样本的 qmd `update` 累计 2.61 秒，平均 87.1 毫秒；该数字只计关键词索引更新，不包含 collection add、文件物化和模型回答。

## 📝 5. 结论与问题定位

- 📝 当前实现对“一个会话里有明确关键词的事实”和“找到最新更新”已经有实际增益。
- 📝 多会话题虽然 4/5 命中答案会话，却 0/5 答对；核心短板是多片段召回、排序、数字聚合和跨时间整合，不只是搜索召回率。
- 📝 12 道题出现“命中答案会话但仍答错”，说明返回片段可能截断、证据不足，或 reader 没有把多个结果组合成最终答案。
- 📝 隐含偏好依赖同义表达和行为归纳，纯关键词检索不够，应该对比 qmd semantic/deep。
- 📝 一个知识更新拒答题被旧信息误导，后续需要基于时间的新旧事实消歧和证据充分性门。
- 📝 当前版本证明“有记忆比没有记忆好”，但 36.7% 仍不足以作为高可靠长期记忆；下一轮优化应优先处理检索质量和命中后的回答质量。

## 📝 6. 下一轮建议

1. 📝 在同一 30 题固定样本上 A/B `keyword`、`semantic`、`deep`，避免样本变化干扰结论。
2. 📝 增加多片段聚合：按会话时间排序、去重、对数值和事件做显式合并，再交给 reader。
3. 📝 增加证据充分性门：召回片段不能直接支持答案时必须拒答，尤其是 `_abs` 和知识更新题。
4. 📝 把检索结果窗口、全文打开次数、命中位置和每阶段 token 分开计量，定位 60% token 开销来自哪里。
5. 📝 优化后再跑 500 题全量，并改用官方指定裁判配置后，才能讨论与官方 leaderboard 的横向可比性。
